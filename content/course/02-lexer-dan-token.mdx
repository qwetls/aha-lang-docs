# Lexer dan Token

Tahap pertama dari setiap kompiler adalah **lexer** (atau *tokenizer*/scanner). Tugasnya sederhana namun krusial: membaca teks mentah dan memecahnya menjadi **token** — unit terkecil yang punya makna.

## Apa Itu Token?

Token adalah pasangan `(jenis, teks)`. Contoh untuk baris `let x = 2 + 3;`:

| Jenis Token | Teks |
|-------------|------|
| `Let` | `let` |
| `Identifier` | `x` |
| `Equals` | `=` |
| `Int` | `2` |
| `Plus` | `+` |
| `Int` | `3` |
| `Semicolon` | `;` |

Perhatikan: spasi dan baris baru biasanya **dibuang** oleh lexer — mereka tidak punya makna struktural.

## Cara Lexer Bekerja

Lexer membaca karakter satu per satu dan mengklasifikasikannya:

- Huruf → awal `Identifier` (atau keyword seperti `let`, `if`, `fn`)
- Digit → awal bilangan `Int` seperti `123` atau `3.14`
- `"` → awal `String` sampai tanda kutip penutup
- Simbol seperti `+`, `-`, `==`, `&&` → operator
- `//` dan `/* */` → komentar, langsung dilewati

Contoh dalam struktur AHA! Lang:

```rust
// baris ini adalah komentar — dilewati lexer

let pesan = "halo" + " dunia";
print(pesan);
```

Token yang dihasilkan baris kedua misalnya:

```text
Let  Identifier("pesan")  Equals  String("halo")  Plus  String(" dunia")  Semicolon
```

## Keyword vs Identifier

Perhatikan: `let` dipecah sebagai token `Let` khusus, bukan `Identifier`. Lexer mengenali beberapa kata sebagai **keyword** yang punya makna khusus di bahasa:

```rust
let if = 5;   // ERROR: "if" adalah keyword
```

Di AHA! Lang, daftar keyword mencakup: `let`, `if`, `else`, `while`, `for`, `break`, `continue`, `return`, `true`, `false`, `fn`, `extern`, dan lainnya.

## Sedikit Intuisi Implementasi

Lexer AHA! Lang cukup ringkas — sekitar 250 baris Rust. Inti logikanya adalah loop yang melihat karakter saat ini, lalu memutuskan token berikutnya:

```rust
// ilustrasi struktur lexer (bukan kode persis)
match current_char {
    'a'..='z' | 'A'..='Z' | '_' => lex_identifier(),
    '0'..='9'                => lex_number(),
    '"'                      => lex_string(),
    '+'                      => lex_plus(),
    '-'                      => {
        // bisa "-" saja, atau komentar "//"
        match peek_char() {
            '/' => skip_line_comment(),
            _   => lex_minus(),
        }
    }
    _ => lex_symbol(),
}
```

Kesalahan — seperti string yang tidak ditutup — juga dideteksi di tahap ini sehingga posisi errornya presisi.

## Ringkasan

1. Lexer memecah teks jadi token.
2. Spasi dan komentar dibuang.
3. Keyword dikenali sejak tahap ini.
4. Error sintaks dasar (seperti string tak tertutup) terdeteksi di sini.
