# Sistem Tipe

AST sudah terbentuk, tapi kompiler belum selesai. Sebelum menghasilkan kode mesin, ada satu pemeriksaan penting: **sistem tipe**.

## Apa Itu Tipe?

Tipe adalah kategori nilai yang menentukan operasi apa yang sah dilakukan padanya. AHA! Lang memiliki tipe-tipe dasar:

| Tipe | Makna | Contoh |
|------|-------|--------|
| `Int` | Bilangan bulat 64-bit | `42`, `-7`, `0` |
| `Bool` | Nilai kebenaran | `true`, `false` |
| `String` | Teks | `"halo"` |
| `Void` | Tidak ada nilai | hasil fungsi yang `return` kosong |
| `Array` | Kumpulan nilai | (dalam pengembangan) |
| `Function` | Fungsi | nilai yang bisa dipanggil |

## Kenapa Perlu Type Checking?

Tanpa pemeriksaan tipe, kesalahan kecil bisa menjadi crash misterius saat runtime:

```rust
let umur = 25;
let nama = "Budi";

// ERROR di compile-time:
let hasil = umur + nama;
//          ^ Int + String tidak valid
```

Karena kompiler tahu `umur` adalah `Int` dan `nama` adalah `String`, ia menolak program sebelum pernah dijalankan. Error muncul di terminal pengembang, bukan di depan pengguna.

## Cara Kerja Type Checking

Setiap node di AST diberi "label" tipe, lalu kompiler memeriksa operasi:

| Operasi | Aturan |
|---------|--------|
| `Int <op> Int` | Valid untuk `+ - * / %`; hasil `Int` |
| `Int == Int`, `Int != Int` | Valid; hasil `Int` 0/1 (boolean ala C) |
| `String == String` | Valid; memakai `strcmp` |
| `String + String` | Valid; konkatenasi |
| `Int && Bool` | **Tidak valid** — tipe tidak cocok |

AHA! Lang memakai pendekatan yang menarik: hasil perbandingan adalah `Int` `0`/`1`, bukan `Bool`. Ini membuat logika mengalir langsung ke aritmetika:

```rust
let benar = 1;
let skor = (umur >= 18) * 2 + benar;  // aritmetika di atas hasil logika
```

## Tipe di Sisi Implementasi

Di rilis 1.4.0, sistem tipe AHA! Lang hidup di `src/types.rs`:

```rust
// ilustrasi enum tipe (bukan kode persis)
enum AhaType {
    Int,
    Bool,
    String,
    Void,
    Array,
    Function,
}
```

Komponen utamanya:

- `check_binary_op(op, left_type, right_type)` — validasi operator biner.
- `check_prefix_op(op, operand_type)` — validasi operator unary seperti `!` dan `-`.
- `TypedValue` — setiap ekspresi codegen kini mengembalikan nilai *plus* tipe-nya, jadi tipe dibawa sampai ke tahap pembuatan kode.

## Type Checking Menyelamatkanmu

Tanpa sistem tipe, bug seperti ini baru ketahuan saat program berjalan:

```rust
let a = "10";
let b = a + 5;   // compile error: String + Int

let c = true + 1; // AHA! membolehkan, karena 0/1 adalah Int
```

Aturan yang konsisten berarti perilaku yang bisa diprediksi.

## Ringkasan

1. Setiap ekspresi punya tipe.
2. Kompiler memvalidasi operasi di compile-time.
3. AHA! Lang memakai `Int` 0/1 sebagai boolean — logika bisa diaritmetikakan.
4. `TypedValue` membawa informasi tipe sampai ke tahap codegen.
